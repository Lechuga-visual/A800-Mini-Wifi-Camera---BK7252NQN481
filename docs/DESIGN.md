# Documentation and UI design

Audience: device owners identifying a board, backing it up and connecting it to Home Assistant.

README direction: restrained technical documentation, native GitHub Markdown, real board photos and user-supplied listing screenshots. DESIGN_VARIANCE 3, MOTION_INTENSITY 1, VISUAL_DENSITY 4. GitHub controls theme and typography. No custom frontend framework, decorative badges, generated hardware imagery or animations.

Keep English and Spanish READMEs aligned. Lead with verified hardware and status. Separate seller claims from measurements. Put commands, recovery and security details in dedicated documents. Link the documents from both READMEs.

Camera UI: preserve the approved warm monochrome direction, system body font and restrained serif heading. No external assets or cloud/CDN dependency. ES/EN selector, labelled fields, visible keyboard focus and narrow-screen layout. First setup prioritizes passwords; it hides the inactive video and Wi-Fi forms until access is configured. UI previews must say their state is simulated.

Preflight: check relative links and image files, no leaked credentials, bilingual coverage, no decorative em dashes, legible screenshots, explicit limitations and correct build commands. Marketing-page animation/framework rules are not applicable to a README rendered by GitHub.
